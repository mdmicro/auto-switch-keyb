# Архитектура Auto Switch Keyb

Документ описывает, как устроен автопереключатель раскладки: от глобального
клавиатурного хука до иконки в трее. Читатель — разработчик, который хочет
править код.

## Схема

```
                    ┌──────────────────────────────────────────┐
                    │ MainThread (pythonw / EXE)               │
                    │  engine.start() ─► SetWindowsHookExW(LL) │
                    │  run_tray()      ─► pystray icon.run()  │
                    │      ├── poll-поток: флаг + sync layout  │
                    │      └── меню → settings.py (Tk)         │
                    └──────────────────────────────────────────┘
   клавиши          │
  ─────────►  hook callback (_on_key)                          
              │  word buffer, детект слова, хоткеи отмены/смены раскладки слова
              ▼                                              
            decide()  (corrector + layout_map + словари)     
              │ action: (набранное, фикс, раскл.набора, раскл.реза, терминатор)
              ▼                                              
            _apply_fix() → replace_last_word() (SendInput)   
                        → switch_layout() (WM_INPUTLANGCHANGEREQUEST)
```

Три сущности с собственной ответственностью:

1. **Хук** (`engine.py`) — единственное место, где «рождается» решение
   исправлять. Работает синхронно в колбэке.
2. **Исполнитель** (`fixer.py`) — атомарная замена текста и смена раскладки.
3. **UI** (`tray.py`, `settings.py`, `flags.py`) — наблюдатель: показывает
   состояние, принимает настройки. Никакой логики исправления в UI нет.

## Модули

### engine.py — движок (`SwitchEngine`)

- **Хук `WH_KEYBOARD_LL`** (`SetWindowsHookExW`), колбэк `_on_key`.
  Колбэки низкоуровневого клавиатурного хука вызываются **только пока
  поток-установщик разбирает сообщения** — в продакшене это делает
  `pystray.Icon.run()`, в тестах — `win32gui.PumpWaitingMessages`.
- **Буфер слова**: символы накапливаются; на границе слова (пробел, Enter,
  Tab, пунктуация, «нечитаемый» символ) слово уходит в `decide()`.
- **Раскладка** читается через `GetKeyboardLayout(tid)` фокусного окна
  (фолбэк на текущий поток — в консоли для чужого потока он иногда NULL);
  LCID `0x0419` = RU, `0x0409` = EN.
- **`intent`** — раскладка, выбранную пользователем сам (Alt+Shift и т. п.),
  движок помечает её как намерение и перечитывает:
  - на keyup модификатора / Caps Lock / Win (мгновенно, ловит Alt+Shift
    и Win+Space);
  - на каждой обычной клавише;
  - из poll-потока иконки каждые 0.4 с (`_sync_layout()`).
- **Хоткей отмены**: совпал VK + ровно нужные модификаторы (Ctrl/Shift/Alt
  по маске) + после фикса не набрано ни символа → откат и «съедание»
  клавиши (`return 1`); иначе хоткей проходит приложению как обычный Undo.
- **Хоткей смены раскладки слова** (`Ctrl+Shift+F` по умолчанию,
  `switch_hotkey`): совпал VK + модификаторы + есть последнее набранное
  слово и после него не печатали → слово перепечатывается «зеркалом» по
  физическим клавишам (без словарей — руками можно менять и словарное
  слово), раскладка переключается; результат откатывается хоткеем отмены.
  В полях паролей не выполняется.
- **Хот-релоад конфига**: настройки — callable (`load_config`), рабочий
  поток перечитывает `config.json` с TTL 2 с; кнопка «Применить» в окне
  настроек дерёт `refresh_now()` (TTL=0).
- **Лог без I/O в хуке**: колбэк кладёт строки в `queue.Queue`, рабочий
  поток пишет файл.
- **Защита от самоисправления**: собственный ввод помечен
  `INJECTED_MAGIC = 0x50535731` в `dwExtraInfo`; такие события игнорируются.

### corrector.py — словари и эвристика

`decide(word, layout, intent, dicts) → {fixed, layout, score}`:

- `len < 3` → не трогаем;
- смешанное письмо (кириллица+латиница в одном слове) → не трогаем;
- `mirror = convert(word)` — «зеркало» (те же клавиши в другой раскладке);
- **правило**: `mirror` есть в словаре **и** `word` в словаре нет → фикс.
  Если оба слова словарные — не вмешиваемся (пользователь мог набрать
  осознанно); если ни одного — тоже не вмешиваемся;
- регистр переносится с оригинала (`ПрИвЕт` → `прИвЕт`).

### layout_map.py — таблица клавиш

Соответствие физическая клавиша → символ для RU/EN (ЙЦУКЕН ↔ QWERTY).
`convert(word, lang)` строит зеркало, `lang_of_chars(word)` определяет,
каким письмом набрано слово.

### fixer.py — исполнение

- `replace_last_word(old, new, term_vk, term_char)` — **одна** пачка
  `SendInput`: `len(old)` × Backspace + символы `new` + терминатор.
  Атомарность гарантирует, что пачка попадёт в очередь ввода раньше
  следующих клавиш пользователя (иначе каретка «разъезжается»).
- Структура `INPUT` **обязательно** с union'ом, включающим `MOUSEINPUT`
  (sizeof == 40 на x64), иначе `SendInput` возвращает 0 с `GetLastError() == 87`.
- Собственные события — с `dwExtraInfo = INJECTED_MAGIC`.
- **Важно про Unicode-ввод**: `KEYEVENTF_UNICODE` приходит в хук как
  `vkCode == VK_PACKET (0xE7)`, сам символ — в `scanCode`. Хук это учитывает.
- Клавиша-терминатор, на которой слово ушло в фикс, «съедается» хуком
  (и её keyup тоже — `_swallow_vk`), терминатор дописывает пачка.
- `switch_layout(layout)` — `PostMessage(WM_INPUTLANGCHANGEREQUEST)`
  фокусному окну. Вызывается **только при реальной смене языка**
  (без смены перемыкает ввод в терминалах, и хук там перестаёт работать).

### tray.py — трей

- Иконка = `flag_image(engine.layout, engine.enabled)`; при смене состояния
  поток `poll()` перерисовывает её (флаг обновляется и при ручной смене
  раскладки — Win+Space и т. п.).
  ⚠️ Поток запускается **до** `icon.run()`, поэтому условие входа в цикл
  — «ждать появления иконки», а не `while icon.visible` (до запуска иконки
  `visible == False`, и цикл выходил мгновенно — флаг не обновлялся никогда).
- Меню: Включено (checked), Русская/Английская раскладка, Настройки…,
  Автозапуск (checked, HKCU\...\Run, для Nuitka-сборки — путь exe через
  `sys.frozen`), Выход (`on_exit()` + `icon.stop()`).

### settings.py — «Настройки» (Tkinter)

Открывается из меню **в отдельном потоке** (немодально, mainloop свой).
Валидация хоткея — `parse_hotkey` (модификаторы Ctrl/Shift/Alt +
буква/цифра, одиночные только F1–F12). «Навести окно…» берёт имя процесса
фокусного окна (`GetForegroundWindow` → `QueryFullProcessImageNameW`).
«Сохранить и применить»: `save_config()` + `engine.refresh_now()`.

### hotkey_config.py, paths.py, flags.py

- `hotkey_config`: схема конфига, `load_config` (fallback на seed-файл),
  `save_config`, `parse_hotkey`/`format_hotkey`.
- `paths`: `resource_path()` ищет данные рядом с exe/исходником/в cwd
  (Nuitka onefile распаковывается во временный каталог — словари лежат
  **рядом с exe**, `__file__` там не работает); `config.json` и лог — всегда
  в `%LOCALAPPDATA%\auto-switch-keyb\` (переживают перезапуск).
- `flags`: флаги рисуются кодом (PIL), картинок в репо нет.

## Словари

- RU: [danakt/russian-words](https://github.com/danakt/russian-words)
  (cp1251, ~1.5 млн форм) → фильтр: длина 2–20, только кириллица, ё→е,
  уникальные → **260 000** кратчайших (сортировка «длина, лекс.» — эвристика
  частотности) → `words/words_ru.json`.
- EN: [dwyl/english-words](https://github.com/dwyl/english-words)
  `words_alpha.txt` → фильтр 2–20, a–z, уникальные → **170 000** кратчайших
  → `words/words_en.json`.
- Словари: JSON → set; загрузка ~0.1 с, чтение через `paths.resource_path`.
- Окно настроек (Tkinter) требует плагина `--enable-plugin=tk-inter`:
  без него в onefile-сборке нет `tcl\init.tcl`, `tk.Tk()` падает
  «Can't find a usable init.tcl» и (до обёртки `_menu_guard`) исключение
  убивало иконку молча.
- Конверсия клавиш в символы — `ToUnicodeEx` с HKL **фокусного окна**,
  модификаторы — `GetAsyncKeyState`. `GetKeyboardState`/`ToUnicode`
  отражают раскладку потока-угонщика хука и в ряде случаев «зеркалят»
  буквы заранее — тогда направление RU→EN молча не работает.

## Ключевые грабли (из практики)

1. `INPUT.union` без MOUSEINPUT → `SendInput` = 0 (err 87). Размер структуры
   на x64 обязан быть 40.
2. `KEYEVENTF_UNICODE`: в хук приходит `VK_PACKET`, символ в `scanCode`
   (`ToUnicode(0, …)` возвращает −1).
3. Колбэк хука живёт только при pumped messages у потока-установщика.
4. `GetKeyboardLayout(чужой tid)` в консоли может вернуть NULL — фолбэк на
   текущий поток.
5. Файловый I/O в колбэке хука ускоряет «подтормаживания» печати — лог
   через очередь и рабочий поток.
6. `WM_INPUTLANGCHANGEREQUEST` без реальной смены языка ломает ввод в
   терминале — слать только при смене RU↔EN.
7. Поток иконки с `while icon.visible:` до `icon.run()` — умирает сразу
   (см. tray.py выше).
